# Visual system

Use this after the strategy in [SKILL.md](../SKILL.md). The project's approved
brand and design direction take precedence over these defaults. Reuse existing
components and tokens. For a new site, establish a small token set from the brief
and concrete references before implementation.

## B1. Typography and copy

Use the project's typefaces, type scale, and voice. Keep text readable at narrow
widths and zoom; balance headings where it helps. Use clear labels and preserve
approved copy. Add a typeface only when the design calls for it.

## B2. Spacing

Use the project's spacing tokens. Keep related content close and separate distinct
sections. Check narrow screens with real content, including long labels.

## B3. Corner radius

Follow the product's shape language. Nested surfaces should have consistent
insets and corners; do not force rounded cards into a square design.

## B4. Borders and backgrounds

Use approved colors and surface treatments. Preserve text contrast and visible
boundaries in each supported theme. Decoration must serve the accepted direction.

## B5. Hero

Make the offer, audience, and primary action clear. Choose line lengths and media
scale for the actual copy and viewport. Use real product imagery where available.

## B6. Icons

Use the existing icon family and accessible labels. Decorative icons should not
repeat information for screen readers. Icons cannot replace unclear wording.

## B7. Motion

Use motion to explain state changes or support the approved visual direction.
Keep controls responsive, honor reduced motion, and ensure content remains
available without animation. Avoid adding a motion library for a simple transition.

## B8. Evidence

Use verified product facts, prices, testimonials, and results. Never fabricate
customer names, brands, metrics, guarantees, or trust signals. Mark draft content
and missing evidence clearly; omit unsupported claims from a finished page.

## B9. Interaction states

Verify the states each control actually needs: keyboard focus, hover, active,
loading, empty, success, and error. Give users a clear recovery path. Navigation
and primary actions must work; avoid placeholder links that appear functional.

## B10. Completion

Inspect the rendered page at desktop and narrow widths. Check keyboard operation,
focus visibility, text contrast, meaningful image alternatives, forms, and links.
Confirm metadata, favicon, routing, and applicable privacy information. Use the
project's checks and approved browser workflow; report anything unverified.
Production publication requires the user's authorization.

## B11. Optional tagline reveal

Include a separate tagline or animated reveal only when the brief or accepted
direction calls for it. Keep the statement readable with reduced motion and
without JavaScript. A small landing page does not need extra sections to be complete.
