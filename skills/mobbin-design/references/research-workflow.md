# Research workflow

## 1. Choose the layer

- Visual language or a single UI state: start with `search_screens`.
- A journey with a before and after: start with `search_flows`.
- A marketing or website section: start with `search_sections`.
- Often you want two layers (for example a paywall screen plus the onboarding flow that leads to it, or a hero section plus a pricing section).

## 2. Search a few tight angles

1. One query for the exact job (paywall, empty state, pricing section).
2. One query for the domain or audience, if that would change the pattern.
3. One query for a known-strong product in the same job, when relevant.
4. Do not page through the whole library. If the first results are weak, tighten the wording and search once more.

## 3. Lock a short reference set

Settle on 3–6 strong references. For each, note the link and one line on what you will take.

```text
Primary reference/direction: [one dominant source]
Preserve: [3–5 traits that must survive: canvas, type, accent, layout, density, media]
Borrow only: [1–2 specific secondary details]
Reject: [defaults or averages that would collapse the direction]
```

When references conflict, keep one dominant direction. Do not average them into a safe middle.

## 4. Adapt to the product

Use the references for hierarchy, spacing, rhythm, and component behavior, and adapt them to this product.

## 5. Optional secondary source

If Mobbin is missing a needed pattern and Refero is connected, you may use `refero-design` as a secondary source. Refero is prepaid through August 2027; it is not the default. Record when a reference came from Refero.
